# Deck studio UI (phases 2-4)

Local studio server and zero-dependency web UI for gentle-decks: Plan stage (editable outline +
look and feel), generation grid, and editor. The agent bridge is files plus stdout events until the
Pi extension (phase 5, out of scope). Branch `feat/studio`. Read `FORMAT.md`, `themes/CONTRACT.md`,
`src/plan.js`, `src/design.js`, `bin/decks.js` first.

## Specs

- S2 — Flow (user, verbatim): "Un review plan en el que tenemos el diseno que escogimos, pero lo mas importante es el outline donde podemos editar el texto, agregar un slide, mesclar slides, mover los slides, etc para que manualmente se pueda modificar y hacer ajustes incluso generar o hacer comentarios a cada slide [Image#3] y ya luego de eso recien comienza a generarse y vemos todos los slides generandose? de ser posible como en un grid y luego ya tenemos la vista de [Image#4] y pues dentro podemos hacer varias cosas de editar manualmente o de poner comentarios del diseno, etc para poder terminar de afinar la presentacion".
- S3 — Editor scope (agreed): text edit, anchored comments, layout switch, ask the agent to redo a slide, thumbnails + large view. Not in scope: freeform positioning, AI images, PPTX.
- S4 — Deck directory: `decks/<slug>/` holds `plan.json`, `<slug>.md` (the deck; `<slug>` = directory name), optional `themes/<name>.css` (proposed themes), and studio files `requests.json`. The CLI theme lookup for a deck checks `<deck dir>/themes/<name>.css` first, then the repo `themes/<name>.css`; a missing theme fails: `build failed: theme not found: <name>` (exit 1, nothing written). `decks theme check <name|path.css>` accepts a CSS path too.
- S5 — `decks studio <deck-dir> [--port N]` starts an HTTP server on 127.0.0.1 only, prints exactly one line `studio: http://127.0.0.1:<port>/<token>/` (token = 32 random url-safe chars) and keeps running. Every route lives under `/<token>/`; anything else is 404. Non-GET requests must carry `Origin: http://127.0.0.1:<port>` (else 403) and `Content-Type: application/json` (else 415); bodies over 1 MB → 413. The `Host` header must be `127.0.0.1:<port>` or `localhost:<port>` (else 403, DNS-rebinding guard). The deck dir must contain `plan.json` (else exit 1 `studio: <dir>/plan.json not found`).
- S6 — `GET api/state` → `{ rev, plan, themes: [{ name, source: "repo"|"deck" }], deck: { exists, slides: [{ id, index, title, status }] }, requests: [...open] }`. `rev` = sha256 hex of plan.json bytes + "." + sha256 of deck bytes (or "none"). Slide `status`: `ready` (in deck, body differs from its scaffold), `draft` (in deck, body equals `scaffoldDeck` output for that plan slide), `pending` (plan slide not in deck). Deck slides not in the plan are listed with `status: "ready"`.
- S7 — `PUT api/plan` body `{ rev, plan }`: 409 `{ error: "stale", rev }` when `rev` differs from the current; 422 `{ error: "invalid", problems }` from `validatePlan`; else writes plan.json atomically (tmp + rename, 2-space JSON + newline) and returns `{ rev }`. The UI supports edit title/points/notes, add, delete, merge with next (titles joined " · ", points concatenated, notes joined, keeps first id), move up/down/drag, per-slide comment (stored as a `comment` request, S9), and theme choice (`plan.theme`).
- S8 — `GET slides/<id>.html` renders that slide as a static artboard (same as `--design` output) from the deck, or from the plan scaffold when the deck lacks it; `?theme=<name>` overrides the theme (look-and-feel previews). The response injects `/<token>/assets/inspector.js`. Slide HTML is served with `Content-Security-Policy: sandbox allow-scripts; default-src 'none'; style-src 'unsafe-inline'; script-src http://127.0.0.1:<port>/<token>/assets/; img-src data:` and the UI loads it in `<iframe sandbox="allow-scripts">`. Unknown id → 404. Build errors → 422 `{ error: "build", message }`.
- S9 — Requests queue `requests.json` `{ version: 1, requests: [{ id, kind, slideId?, text?, selector?, excerpt?, layout?, status: "open"|"resolved", createdAt, resolvedAt }] }`. Kinds: `generate` (approve plan and generate), `comment` (plan or design comment on a slide/element), `redo` (rewrite a slide, text = instruction), `layout` (switch component, `layout` = container name from the renderer list), `add-slide` (after `slideId`, text = idea), `overflow` (slide content taller than 900px, reported by the UI). `POST api/requests` validates kind and fields (422 otherwise) and appends; duplicates of an open `overflow` for the same slide are ignored. Each accepted request prints one stdout line `request <id> <kind> <slideId|->` so an agent monitoring the process reacts live. `decks studio requests <deck-dir>` prints open requests as JSON; `decks studio resolve <deck-dir> <id...>` marks them resolved (unknown id → exit 1 `unknown request <id>`, nothing changed).
- S10 — `PUT api/slides/<id>/text` body `{ rev, before, after }` (inline text edit): finds `before` (trimmed, non-empty, single line; `after` must also be single-line, else 422 `$.after: must be a single-line string`) in that slide's markdown source only; exactly one occurrence → replaced, deck rewritten atomically, returns `{ rev }`; zero → 404 `{ error: "not-found" }`; several → 409 `{ error: "ambiguous" }` (the UI then offers a comment instead). Stale rev → 409 stale. Never touches other slides or directives.
- S11 — `GET api/events` is Server-Sent Events: `event: change` with `data: {"rev":"...","themes":"<sha256 of deck-local theme files>"}` whenever plan.json, the deck, requests.json, or deck themes change (poll file stats ≤ 500 ms), plus a comment heartbeat every 15 s. The grid fills live as the agent writes slides.
- S12 — `GET present` returns the full navigable deck (same bytes as `-o`) for the current deck, served with `Content-Security-Policy: sandbox allow-scripts; default-src 'none'; style-src 'unsafe-inline'; script-src 'unsafe-inline'; img-src data:` so deck HTML cannot reach the studio API; 404 when the deck does not exist.
- S13 — UI (`studio/` static assets, no dependencies, no build step, no external URLs): Plan stage when the deck does not exist (outline editor left, look-and-feel right with theme cards previewing cover + 2 plan slides per theme, "Generate" button posting a `generate` request); Grid stage when the deck exists and some plan slide is `pending`/`draft` or by toggle (all slides scaled in a grid, placeholders for pending, live via SSE); Editor stage (thumbnail rail, large slide view scaled to fit, toolbar: comment mode, edit-text mode, layout select, "Redo with agent", add slide, present link, open-requests panel). Overflow badge on slides the inspector reports. Keyboard accessible, visible focus, WCAG AA, `prefers-reduced-motion`.
- S14 — Existing contract holds: `-o`/`--design` outputs unchanged for decks without deck-local themes; all existing checks pass; usage lists the new commands.
- S15 — Skill and docs describe the studio flow and the request bridge; README lists the studio.

## Log

- L1 (user): see S1 verbatim.
- L2 (decision): zero-dependency HTML/JS UI served by a Node `http` server in this repo (recommended option; no framework, no build). Agent bridge = `requests.json` + stdout `request …` lines (watchable with the monitor tool) until the Pi extension.
- L3 (decision): no headless browser library is installed; UI verification uses the HTTP API tests plus a headless Chromium (`/Applications/Chromium.app`) screenshot smoke check.
- L4 (contract shared by T1 and T2, so both run in parallel): static UI assets live in `studio/` (owned by T2) and are served by T1 at `/<token>/` (`index.html`) and `/<token>/assets/<file>` from `studio/`. The inspector `studio/inspector.js` is owned by T1. postMessage protocol (artboard → parent, `*` target, parent validates `event.source` is a known iframe): `{type:"gd:ready", slideId, overflow:boolean, height:number}` on load and resize; `{type:"gd:pick", slideId, selector, excerpt, text}` on click in comment or edit mode. Parent → artboard: `{type:"gd:mode", mode:"view"|"comment"|"edit"}`. In `edit` mode the inspector makes the clicked text element `contenteditable`, and on blur posts `{type:"gd:edit", slideId, before, after}` (innerText before/after, trimmed). Overflow = `document.querySelector('.slide').scrollHeight > 900`.
