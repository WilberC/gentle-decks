Decks · Markdown a presentación

Presentar ya no es
escribir HTML a mano.

Escribís el contenido en markdown, el renderer aplica el tema y produce un solo archivo HTML autocontenido. Navegación, responsive y export a PDF incluidos.

El problema

Hoy cada deck es artesanal

✍️

HTML a mano

Cada slide es HTML escrito a mano: caro de corregir y sin template real.

🎨

Tema copiado y pegado

El CSS es idéntico en cada deck, pero vive copiado dentro de cada gist.

El contenido debería ser markdown. El resto, mecánica.

La idea

Un skill, un renderer, el canvas

01 Escribí El agente escribe el contenido en markdown con convenciones simples.
02 Renderizá Un comando convierte el markdown en un HTML autocontenido, siempre igual.
03 Miralo El deck se abre en el canvas de gentle-design, con comentarios.
El formato

Markdown con intención

El markdown mapea directo: # título, ## slide, > cita, tablas y listas estándar. Los componentes especiales son containers:

grid-2 card step term bars stat

# ejemplo real de este deck
::: split
texto a la izquierda…
::: card accent icon=⚡
tarjeta destacada
:::
:::
Los números

Por qué conviene

1archivo

El deck completo viaja en un solo HTML, sin dependencias externas.

0repetición

El tema vive en un único CSS del paquete, no copiado por deck.

PDFincluido

La tecla P exporta una slide por página, listo para compartir.
